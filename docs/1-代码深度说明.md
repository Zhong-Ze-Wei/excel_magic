# 代码深度说明 — 这个项目到底在做什么

## 一句话总结

Magic Excel 是一个**纯前端 Excel 智能处理平台**，用户上传 Excel/CSV 文件后，可以借助 AI 大模型进行数据清洗、批量翻译、评论分析、数据摘要和公式生成。所有数据处理在浏览器端完成，AI 能力通过调用第三方大模型 API 实现。

---

## 项目解决的核心问题

在电商运营、数据分析等场景中，常见的痛点是：

1. **脏数据清洗** - 社媒评论中混杂大量表情、乱码、广告、重复水贴，人工筛选效率极低
2. **批量翻译** - 产品参数、用户评论需要翻译成多语言，逐条翻译耗时
3. **评论分析** - 海量评论需要提取情感倾向和分类标签，纯人工无法规模化
4. **数据摘要** - 拿到一张新表需要快速了解数据特征和业务洞察
5. **公式生成** - 复杂 Excel 公式记不住语法

本项目用一个统一的 Web 界面，把这五个场景串起来，并且通过"全局数据总线"让数据在模块间无缝流转，实现"一次上传，多步处理"。

---

## 技术架构本质

```
用户浏览器
  │
  ├── Vue 3 SPA (单页应用)
  │     ├── Pinia Store (状态管理)
  │     │     ├── dataShare → 全局数据总线，模块间共享 Excel 数据
  │     │     ├── settings  → API Key、模型选择、清洗规则配置
  │     │     └── data      → 基础数据容器
  │     │
  │     ├── Services (业务逻辑层)
  │     │     ├── ai.js          → 封装 OpenAI 兼容 API 调用
  │     │     ├── excel.js       → SheetJS 读写 Excel/CSV
  │     │     ├── cleaningRules.js → 10 种原子清洗规则引擎
  │     │     └── prompts.js     → 所有 AI Prompt 模板
  │     │
  │     └── Views (7 个页面)
  │           ├── 首页、清洗、翻译、分析、摘要、文本翻译、公式
  │
  └── 调用外部 API ──→ 硅基流动 / aiping.cn (OpenAI 兼容接口)
```

**关键点：没有后端。** 用户的 Excel 数据不会上传到任何服务器，只有需要 AI 处理的文本片段会发送到第三方大模型 API。

## 六大功能模块概览

### 1. 数据清洗 (`/cleaning`)
- 10 种内置原子规则：空文本、字数过短、精确去重、纯表情、纯标点、纯链接、纯话题、短无意义词、引流广告、乱码
- 自定义筛选规则：文本包含/不包含、正则匹配、列值匹配、数值比较等
- AI 智能筛选：用自然语言描述意图（如"过滤掉负面评论"），AI 自动生成精确匹配规则
- 审计模式：不直接删除，而是打标 keep/delete/suspect，用户可在表格中逐行确认

### 2. 批量翻译 (`/translate`)
- 5 种翻译场景：产品参数、用户评论、竞品标题、邮件沟通、通用翻译
- 4 种语言方向：自动→中文、中→英、英→中、中→日
- 逐行调用 AI 翻译，实时显示进度

### 3. 评论分析 (`/analysis`)
- AI 驱动的情感分析：Positive / Negative / Neutral
- 双层树状标签分类：一级大类 + 二级子标签
- AI 智能生成分类体系：根据样本评论自动提炼标签
- AI 推荐评论列：自动识别哪一列是评论内容
- 支持自定义 System Prompt 和分析目标

### 4. 数据摘要 (`/summary`)
- 流式输出：AI 实时生成分析报告
- 自动提取数据统计特征和业务洞察
- 支持 Markdown 格式渲染

### 5. 文本翻译 (`/text`)
- 快速翻译单段文本
- 通用翻译场景，自动检测源语言

### 6. 公式生成 (`/formula`)
- 自然语言描述需求，AI 生成 Excel 公式
- 返回公式 + 使用说明

## 核心设计思想

### 1. 全局数据总线
`dataShare` store 是整个项目的数据枢纽。用户在首页上传 Excel 后，数据存入总线，所有子模块自动读取。清洗模块处理完后，可以把清洗后的数据写回总线，供翻译/分析模块继续使用。避免用户重复上传。

### 2. 启发式列推荐
系统通过"平均文本长度最长"的启发式算法，自动推荐最可能包含核心内容（如评论文本）的列。用户也可以手动切换或让 AI 推荐。

### 3. 审计优先
数据清洗不直接删除数据，而是给每行打标（保留/删除/待确认），用户在审计表中可以逐行覆写决策。这是为了防止 AI 误判导致数据丢失。

### 4. 配置全持久化
API Key、平台选择、模型选择、清洗规则参数全部保存到 localStorage，刷新页面后自动恢复。还支持导入/导出配置 JSON 备份。

## AI 调用机制

项目通过 `ai.js` 封装了两种调用模式：

1. **非流式调用** (`callAI`) - 发送请求，等待完整响应返回。用于翻译、分析等需要精确结果的场景。
2. **流式调用** (`callStreamingAI`) - 通过 SSE (Server-Sent Events) 逐步接收响应。用于数据摘要等需要实时展示的场景。

两个函数都从 `settings` store 读取当前平台的 API URL、Key 和模型 ID，构造 OpenAI 兼容格式的请求体。

支持的 API 平台：
- **硅基流动 (SiliconFlow)** - SiliconCloud 平台
- **aiping.cn** - AI 聚合开放平台

每个平台分别配置翻译专用模型和常规分析模型，用户可自由选择或输入自定义模型 ID。
