# 0001 — 纯前端架构 + 用户自带 API Key

## 状态

接受

## 背景

项目定位是"个人数据处理工具"，需要决定是否搭建后端服务。

## 决策

纯前端 SPA，无后端。AI API Key 由用户自行在前端配置，存 localStorage，前端直接调用第三方 LLM API。

## 理由

- **零部署**：打包成静态文件即可分发，不需要服务器、域名、SSL
- **数据隐私**：用户数据在浏览器内处理，不经过任何中间服务器。这是纯前端架构最大的差异化优势
- **个人工具定位**：不需要多用户、不需要持久化存储、不需要协作
- **开发成本**：一个人维护，后端意味着多一套部署和运维

## 代价

- **API Key 暴露**：前端明文存 localStorage，打开 DevTools 即可获取。用户需要自行承担 Key 的安全责任
- **数据规模上限**：浏览器内存限制，SheetJS 解析大文件（>50MB）会卡顿或白屏。实测 5 万行以内基本流畅
- **无并发能力**：AI 调用从前端逐个发起，受浏览器连接数限制。`callAIBatch` 通过信号量控制并发（默认 3 路），但仍受限于浏览器
- **无用户认证**：不支持多设备同步、不支持团队协作、不支持定时任务

## 触发条件：什么时候该加后端

当以下任一条件满足时，考虑加轻量后端（FastAPI / Cloudflare Worker）：
1. 需要处理 >5 万行数据（浏览器内存瓶颈）
2. 需要保护 API Key 不暴露给用户
3. 需要批量并发 AI 调用（>10 路并发）
4. 需要定时任务或团队协作

加后端时只做薄代理层（API Key 安全转发 + 大数据统计 + 批量 AI），前端继续负责 UI 和小数据本地处理。
