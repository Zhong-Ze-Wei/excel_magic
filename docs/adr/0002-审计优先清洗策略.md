# 0002 — 审计优先的数据清洗策略

## 状态

接受

## 背景

数据清洗模块需要决定如何处理"脏数据"。两种路线：直接删除 vs 先标记再由用户裁决。

## 决策

审计优先：每条规则不直接删除数据，而是为每行打标（keep / delete / suspect），用户在结果表中逐行查看、可覆写决策，确认后再导出。

## 理由

- **AI 判断不可信**：规则和 AI 都有误判。直接删除会丢失用户需要的数据，且不可恢复
- **用户有最终裁决权**：不同场景对"脏数据"的定义不同。运营认为的垃圾评论，可能正是客服需要分析的样本
- **可审计**：用户能看到每行被标记的原因（`reason` 字段）和置信度（`confidence` 字段），而非黑盒

## 体现

- `cleaningRules.js` 的每个规则函数返回 `{ hit: boolean, reason: string, confidence: number }` 而非布尔值
- `runCleaningPipeline` 汇总所有规则命中结果，生成每行的最终状态和置信度
- `CleaningView.vue` 的结果表用颜色区分状态（绿=保留，红=待删，黄=可疑），用户可逐行切换
- 自定义规则（`CustomFilterForm`）同样遵循 keep/delete/suspect 三态

## 代价

- 用户需要手动确认，无法"一键全自动清洗"
- UI 比直接删除复杂（结果表 + 覆写交互 + 状态统计）
