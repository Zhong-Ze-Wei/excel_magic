# 0005 — 移动端双模板架构

**日期**: 2026-05-30
**状态**: 已采纳
**分支**: feat/mobile-ui

## 背景

Magic Excel 的桌面端 UI 基于左侧 Sidebar + 右侧内容区的经典布局。随着用户开始在手机端使用，需要适配移动端。核心矛盾：桌面端的宽屏布局（Sidebar + 多列表单 + 宽表格）在 768px 以下完全不可用。

## 决策

采用**双模板完全分离**策略，而非渐进式响应式断点。

### 架构分层

```
App.vue → useDevice() → isMobile?
├── false → DesktopLayout（Sidebar + Header + router-view）
└── true  → MobileLayout（MobileHeader + router-view + MobileTabBar）
```

每个 View 文件内部用 `v-if="isMobile"` / `v-else` 维护两套独立模板，共享同一个 `<script setup>` 逻辑层。

### 关键设计

1. **设备检测**：`useDevice()` 用 `matchMedia('(max-width: 768px)')` 监听，模块级单例，所有组件共享同一个响应式 `isMobile` ref。不做 resize 防抖——matchMedia 的 `change` 事件本身只在断点穿越时触发，不是连续事件。

2. **布局壳分离**：App.vue 只做条件渲染（~15 行），DesktopLayout 和 MobileLayout 各自封装完整的布局结构。移动端用底部 Tab Bar（5 个 tab）替代 Sidebar，用 MobileHeader 替代 Header。

3. **功能页内分离**：每个 View 的 template 顶部 `v-if="isMobile"` 分叉。移动端模板使用 MobileCollapsible（可折叠面板）组织信息密度，使用 MobileTableWrapper（横向滚动）处理宽表格。桌面端模板原样保留。

4. **表格不做卡片化**：保留表格形式，用 `overflow-x: auto` 横向滚动。原因：用户的核心操作是"看数据"，卡片视图会丢失列间对比关系。缩小 padding（`px-2 py-1.5`）和字号（`text-xs`），第一列 sticky，表头 sticky。

5. **设置弹窗全屏化**：移动端 SettingsModal 从居中弹窗改为 `fixed inset-0` 全屏覆盖，grid-cols-2 改为 grid-cols-1。

### 为什么不选响应式断点

- 项目用 Tailwind 但没有设计系统，桌面端和移动端的交互模式差异大（Sidebar vs TabBar、平铺 vs 折叠面板），用 `md:` 前缀渐进适配会导致大量条件 class 堆叠，可读性差。
- 双模板虽然有代码重复（template 部分），但每个模板的意图清晰——改移动端不影响桌面端，改桌面端不影响移动端。script 逻辑完全共享，重复只在展示层。
- 对于小团队/个人项目，维护两套 template 的成本低于维护一套响应式断点。

### MobileTabBar 只放 5 个 tab

桌面端 Sidebar 有 10 个路由入口。移动端 Tab Bar 只放 5 个（首页、清洗、翻译、分析、摘要），其余 5 个（列变换、分组、提取、公式、对比）需要从首页或其他入口跳转。理由：底部 Tab 超过 5 个会挤压触摸区域，且核心使用路径（上传→清洗→翻译→打标→摘要）覆盖了 90% 的场景。

## 后果

- 每新增一个 View 需要写两套 template（桌面端 + 移动端），增加约 30-50% 的模板代码量
- 移动端和桌面端可以独立演进，互不干扰
- 设备检测是全局单例，切换浏览器窗口大小时实时响应，无需刷新
- 移动端的信息架构完全由折叠面板控制，用户可以选择展开/收起感兴趣的区域
