# 0006 — 意图驱动上传

**日期**: 2026-06-24
**状态**: 已采纳
**分支**: feat/import-intent-dialog

## 背景

v0.0.3 之前，上传 Excel 后的入口体验是「系统猜」：

1. **启发式列检测**：取前 15 行平均文本长度最长的列作为「核心列」，写入 `dataShare.coreColumn`
2. **模块推荐**：基于数据特征（行数、列类型分布、文本列占比）打分，按分数推荐「最该用的 3 个功能页」，显示在首页

问题：

- **猜错率高**：文本最长 ≠ 业务核心列（评论区里 ID 列可能比评论本身更长；时间戳列长度稳定但不该是核心）
- **决策压力外移**：模块推荐让用户看到「系统觉得你该干什么」，反而造成选择焦虑
- **意图黑盒**：系统不知道用户为什么上传这份数据，AI 调用缺乏任务上下文
- **修正成本高**：用户若不认可启发式结果，需要分别去 HomeView 改核心列、忽略推荐、自己跳路由

## 决策

改为「意图驱动」：上传后弹 `ImportIntentModal`，让用户显式声明意图。

### 意图模型

```js
// stores/importIntent.js
{
  coreColumnIdx: number | null,        // 核心处理列（必填）
  tasks: { clean, process, summary },  // 任务多选
  note: string,                        // 任务说明，≤500 字，作 AI 上下文
  confirmedAt: number | null,          // 提交时间戳
  showModal: boolean,                  // 弹窗显隐
  pendingFileMeta: { name, rowCount, colCount, headers }  // 待确认文件元信息
}
```

### 流程

```
useFileUpload.handleFile()
  ↓ readFile → setSharedData(..., autoDetect=false, {sheets...})
  ↓ 自动 intent.open(fileMeta)
ImportIntentModal 显示
  ↓ 用户选择核心列 + 勾选任务 + 填说明
  ↓ intent.submit() → dataShare.setCoreColumn(idx)
HomeView 显示「数据集意图卡」+ 根据选中 tasks 显示快捷入口按钮
  ↓ 点击跳转 /cleaning | /process | /summary（带着意图上下文）
```

### 关键设计

1. **核心列由用户选**：用户对自己的数据最了解。下拉框列出所有列名，让用户挑。`setSharedData` 的 `autoDetect` 参数保留但失效（向后兼容签名，避免大面积改调用方）。

2. **任务多选 + 自由说明**：clean/process/summary 三个任务是原子粒度，多选覆盖复合场景（如「先清洗再翻译」）。`note` 字段是关键——它会作为 AI 调用的 system context，让清洗/加工/摘要更贴合用户实际意图。

3. **任务字段演化与兼容**：原任务模型是 `{ clean, translate, analyze, summary }` 4 项，功能区合并后（见 [0007](0007-功能区入口收敛.md)）改为 `{ clean, process, summary }` 3 项。`ImportIntentModal` 的 watch 中做向后兼容：旧的 `translate`/`analyze` 字段合并到 `process`，老用户存留的状态不会丢。

4. **意图卡 + 快捷入口**：HomeView 显示当前意图状态（核心列 + 选中任务），并根据 `tasks` 显示对应的快捷入口按钮。点击跳转时，目标页可以从 importIntent 读上下文（AnalysisView 把 `note` 当 system context）。

### 为什么不用启发式

- 启发式错误率高于用户手动选择的错误率
- 用户的 `note` 是免费的语义上下文，启发式拿不到
- 模块推荐的质量依赖特征工程，维护成本高于弹窗交互
- 显式表达比隐式猜测更可解释——用户能看到自己声明了什么，系统也能引用

## 后果

- 上传多一步交互（弹窗 + 提交），但减少了在错误猜测下走到死胡同的概率
- AI 调用拿到 `note` 作为上下文，方案生成和打标结果的相关性提升
- 旧的启发式逻辑全部移除：`computeCoreColumn`、`recommendations`、`autoDetect` 实质失效
- `importIntent` 成为继 `dataShare` 之后的第二个全局状态枢纽，所有功能页都可以读
