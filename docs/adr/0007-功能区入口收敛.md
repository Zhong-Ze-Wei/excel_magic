# 0007 — 功能区入口收敛（5→3）

**日期**: 2026-06-25 ~ 2026-06-26
**状态**: 已采纳
**分支**: feat/smart-process-merge / feat/cleaning-hub-merge

## 背景

v0.0.3 时期有 5 个功能区，造成心智负担：

| 入口 | 用户疑惑 |
|------|---------|
| 数据优化 vs 数据清洗 | 「该用哪个？优化是不是包含清洗？」 |
| 批量翻译 vs 数据分析 | 「翻译是不是分析的一种？打标也是 AI 处理列啊」 |
| 数据摘要 | （无歧义，独立） |

实际职责高度重叠：

- **翻译 / 数据分析**：本质都是「源列 → AI → 新列」，底层共用 `callAIBatch`，差异只在 prompt 构造
- **优化 / 清洗**：本质都是「配置清洗规则 → 跑 pipeline」，共用 `runCleaningPipeline` 引擎，差异只在用户使用习惯（自上而下 vs 自下而上）

用户原话：「**内部都一样，只是用户使用习惯不一样；入口应该更克制**」。

## 决策

分两阶段合并，每个阶段一个独立分支，可独立验证回滚。

### 阶段 1（2026-06-25）：翻译 + 分析 → 智能加工（5→4）

**路由**：`/process`（AnalysisView 实现），`/translate` 和 `/analysis` 重定向到 `/process`。

**核心策略**：翻译降级为预设模板。

- 在 `services/prompts.js` 加 `PRESET_TEMPLATES`（translate_zh/en/jp + sentiment + category）
- 模板按钮点击 → `getPresetPlan(templateId, coreColumn)` 直接构造 `labelingPlan` 对象
- 跳过 `generateLabelingPlanWithAI`，但**完全复用** `compileLabelingPrompt` + `startLabeling` 流程
- 翻译产出的「翻译列」走打标流程，结果存 `labelingResults`（不再走旧的 `addTranslatedColumn` 覆盖 rows）

**过渡期处理**：TranslateView 不删，加蓝色迁移横幅指引用户去 `/process`。`/translate` 重定向而非 404。计划一周后清理。

### 阶段 2（2026-06-26）：优化 + 清洗 → 数据清洗双模式（4→3）

**路由**：`/cleaning`（新建 `CleaningHub.vue` 包装器），`/optimize` 重定向到 `/cleaning`。

**核心策略**：双模式共享同一份规则配置。

```js
// settings.js 新增
cleaningMode: 'simple' | 'expert'  // 默认 simple，持久化
lastAiConfigAt: number | null       // 会话内：是否跑过 AI

// CleaningHub.vue
<OptimizeView v-if="mode === 'simple'" />
<CleaningView v-else />
```

**关键设计**：消除 `OptimizeView` 的本地 `aiRulesConfig` ref，改为 computed from `settings.rulesConfig`：

```js
// 改造前
const aiRulesConfig = ref(null)
function runAiOptimize() { ...; aiRulesConfig.value = config }
function tuneInCleaning() {
  Object.assign(settings.rulesConfig, DEFAULT_RULES_CONFIG, aiRulesConfig.value)
  router.push('/cleaning')
}

// 改造后
const aiRulesConfig = computed(() => settings.lastAiConfigAt ? settings.rulesConfig : null)
function runAiOptimize() { ...; Object.assign(settings.rulesConfig, config); settings.lastAiConfigAt = Date.now() }
// tuneInCleaning 删除——模式切换由 Hub 顶部按钮替代
```

模式切换无缝衔接：AI 跑完方案 → 切专家模式调一条规则 → 切回简易模式立即反映修改，全程同一份 `settings.rulesConfig`。

### 共同原则

1. **入口克制，内部丰富**：每个入口顶部有模式/模板切换栏，提供不同使用习惯的入口，但用户看到的是单一概念。
2. **数据流统一**：合并不只是 UI，更是数据真源。双模式共享 store 字段，避免「本地 ref vs 持久 store」的二元状态。
3. **向后兼容**：旧路由重定向而非删除（`/translate`、`/analysis`、`/optimize` 都还在）；旧 task 字段（translate/analyze）通过 watch 合并到新字段（process）。
4. **渐进迁移**：TranslateView 保留过渡期，给老用户适应时间，等使用数据下降再清理。

## 后果

- 入口数：5 → 3（主页 / 数据清洗 / 智能加工 / 数据摘要，主页是分发器不算功能区）
- 用户叙事：从「5 个工具该用哪个」变成「3 步流水线：清洗 → 加工 → 摘要」
- 翻译不再是独立概念，降级为智能加工的预设模板之一
- 清洗和优化共用 `settings.rulesConfig`，模式切换实时反映修改
- 旧的 `tuneInCleaning` 跳转逻辑删除，被 Hub 顶部模式切换按钮替代
- 待清理：TranslateView、`TRANSLATE_SCENARIOS`、`translationCache.js`、`addTranslatedColumn` action（一周观察期后）
