# 0008 — 意图上下文分层注入

**日期**: 2026-07-01
**状态**: 已采纳
**分支**: refactor/intent-context-as-reference
**前置**: [0006 — 意图驱动上传](./0006-意图驱动上传.md)

## 背景

ADR 0006 把上传流程改为意图驱动后，意图弹窗收集了「核心列 + 任务 + 任务说明」。
其中"任务说明"（`intentNote`）本意是作为 AI 模块的共享上下文。

初版实现把 `intentNote` 直接注入三个功能区时，方式不统一且存在冲突：

| 模块 | 初版注入方式 | 问题 |
|------|------------|------|
| 智能加工 | `onInit` 时 `userGoal.value = intentNote` | **覆盖**：把宏观任务说明塞进微观目标字段，粒度混淆；用户在页面改了 userGoal，下次回来逻辑分支依赖 userGoal 是否为空 |
| 清洗（简易） | 拼进 system prompt 自定义字符串 | 方式孤立，无统一 helper |
| 摘要 | 未注入 | 读不到意图，上下文断裂 |

核心矛盾：**数据集整体意图（宏观）与各模块的步骤目标（微观）是两个层次**，初版把它们混进同一字段，AI 无法区分主次。

## 决策

**意图上下文以「参考段」形式分层注入，不覆盖各模块自己的目标字段。**

### 1. 统一 helper：`formatIntentContext(note, stepFocus)`

新增纯函数（`services/prompts.js`），输出固定格式：

```
【数据集整体任务（参考）】{note}
本步骤请聚焦：{stepFocus}。
```

- `note` 为空 → 返回空串，对无意图场景零影响
- `stepFocus` 标注本步骤在整体任务中的位置，让 AI 理解"宏观任务 → 本步聚焦"的层级

### 2. 三模块统一为「system prompt 追加参考段」

| 模块 | 自己的目标字段（保留不动） | 注入的参考段 stepFocus |
|------|------------------------|----------------------|
| 智能加工 | `userGoal`（页面内可改） | 为表格新增列 |
| 清洗（简易） | system prompt 基础角色 | 数据清洗 |
| 摘要 | `analysisTheme` | 数据摘要与洞察 |

注入点统一在各模块**调 `callAI`/`callStreamingAI` 前、对 system prompt 字符串追加**，不改任何 prompt 生成函数的签名（保持函数纯粹）。

## 备选方案

### A. 保留初版「覆盖 userGoal」方式（否决）
- 缺点：粒度混淆，用户改 userGoal 后语义不清，三个模块方式不统一

### B. 彻底删除意图上下文注入（否决）
- 缺点：意图弹窗的"任务说明"退化为纯 UI 填表便利，失去跨模块上下文价值
- 否决理由：意图上下文能让每个模块的 AI 知道"整个数据集要干嘛"，对清洗/加工/摘要的联动有真实增益

### C. 本方案：参考段分层注入（采纳）
- 优点：宏观/微观分层清晰，模块自治，统一 helper 易维护
- 代价：每个模块调用 AI 处多一行字符串拼接（可接受）

## 影响

- 撤销 `AnalysisView.onInit` 里对 `userGoal` 的覆盖赋值
- `prompts.js` 新增 `formatIntentContext` 导出
- 清洗/摘要补上此前缺失/孤立的注入，三模块行为对齐

## 验证

- build 通过
- 无意图（intentNote 为空）时，三模块 prompt 与改造前完全一致（helper 返回空串）
- 有意图时，system prompt 末尾追加参考段，userGoal/theme 等字段不受影响
