# ADR 0011：纯前端服务边界与兼容入口

- 状态：已采用
- 日期：2026-10-01

## 背景

项目继续采用纯前端架构，本轮不调整页面功能、处理规则或 AI 提示词。已有清洗、画像、打标和分组统计服务能够复用，但 AI 服务直接读取 Pinia 设置，提示词集中在一个文件，Excel 服务混合浏览器读写、解析和示例数据，增加了独立验证的成本。

## 决策

1. 保留 Vue、Pinia、Vite 和静态部署方式，不引入服务端、原生外壳或新的运行时依赖。
2. `services/ai.js` 保留原入口，负责获取设置；`ai/client.js` 接收显式配置执行请求；`ai/batch.js` 接收任务执行函数进行调度。
3. 按上下文、意图、清洗、打标、摘要、预设和能力约束拆分原提示词文件，`services/prompts.js` 显式导出原有接口。
4. `services/excel.js` 保留文件校验、浏览器读写及原公开接口；工作簿编解码放入 `excel/workbook.js`；示例数据放入 `data/demoData.js`。
5. 使用旧入口兼容现有页面，避免一次性迁移所有调用方。纯业务模块不反向依赖这些兼容入口。

## 行为约束

- AI 批次中的每个请求仍在实际开始时读取当前配置，不在批次开始时固定整批配置。
- 普通请求和流式请求原有的 system prompt 差异、模型选择、参数、回调和错误保留。
- 提示词文字、导出名称、函数参数、预设值与对象复制方式保持一致。
- Excel 的扩展名校验、编码、空表处理、缺失 Sheet、错误文案和导出内容保持一致。
- 不改变设置存储键、页面数据流或简易/专家模式的交互。

## 取舍

增加少量文件和兼容转发，换取可以直接测试的请求、调度、提示词和文件解析边界。保留原路径可减少回归面，也使各项拆分能够独立撤销。

这里没有引入通用 AI Provider 框架、插件系统、通用 Repository 或 monorepo；当前需求尚不需要这些抽象。后续若需要桌面外壳或 Worker，可以围绕环境相关入口继续调整，但本次不保证这些运行环境已经适配。

模块独立不等于任务能在关闭页面后继续运行；拆文件也不等于包体积或运行速度自动下降。原有连续限流调度和 SSE 跨分片解析问题另行处理，避免把行为修复混入结构重构。

## 验证

为 AI 请求与调度、提示词契约、Excel 导入导出添加测试；用原提示词实现与拆分后实现逐项对照代表性输入输出。合并前运行全部单元测试和生产构建，不发送真实 AI 请求。
