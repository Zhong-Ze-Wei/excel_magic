# 产品说明

## 产品定位

Magic Excel 是一个纯前端的 Excel/CSV 智能处理平台。用户上传 Excel 文件后，在浏览器内完成数据清洗、智能加工、数据摘要，无需安装任何软件，无需后端服务。

核心价值：**让不会写代码的人也能用 AI 处理表格数据。**

## 用户前提

- 用户自行提供 AI API Key（硅基流动或 aiping.cn 平台）
- 数据在浏览器内处理，不上传到任何服务器
- 支持 xlsx、xls、csv 格式
- 支持多 Sheet 读取，可在首页切换 Sheet

## 三大功能模块（入口收敛后）

重构后从 4 个分散功能页收敛为 3 个统一入口。上传后弹意图弹窗收集「核心列 + 任务」，替代旧的自动检测。

### 1. 数据清洗（CleaningHub，`/cleaning`）

**解决的问题**：用户有一列文本数据（评论、反馈等），混杂空行、重复、纯表情、乱码、广告引流等脏数据，需要清洗。

**双模式统一入口**（用 `settings.cleaningMode` 切换）：

- **简易模式（OptimizeView）**：小白入口。用一句话描述意图（如「删掉所有无意义的评论」），AI 自动生成规则配置，一键出结果。suspect 直接降级为 delete。AI 配置存于组件内存态，**用完即弃不持久化**，不污染专家模式的 `settings.rulesConfig`。
- **专家模式（CleaningView）**：专家入口。手动勾选规则开关、调参数，保留 keep/delete/suspect 三态审计，可人工覆写，配置持久化到 settings.rulesConfig，支持 JSON 导入导出。

**规则体系**（两种模式共享 `runCleaningPipeline` 引擎）：
- **强删规则**（默认开启）：空文本、过短、精确重复、纯链接、纯表情、纯符号、纯话题标签、短无意义词
- **弱规则**（可选策略）：疑似广告引流、疑似乱码
- **自定义规则**：8 种匹配类型（包含/不包含/精确/正则/长度/列匹配/数值比较）
- **AI 智能筛选**：自然语言描述意图，AI 生成精确匹配规则

**关键设计**：审计优先，不直接删除。每条规则返回置信度，用户有最终裁决权。

**统计图表**：执行清洗后显示 ECharts 环形饼图，直观展示保留/删除/可疑分布。

### 2. 智能加工（AnalysisHub，`/process`）— 双模式

**解决的问题**：用户想用 AI 为每行新增分析列（情感倾向、问题分类、翻译结果等），不想手动逐行标注。

**双模式统一入口**（用 `settings.processMode` 切换，ADR 0009）：

- **简易模式（AnalysisSimpleView）**：模板驱动。选预设模板（翻译中/英/日、情感打标、主题分类）或让 AI 根据数据生成方案，一键打标，一键导出。适合快速出结果。
- **专家模式（AnalysisView）**：精细配置。手搓 outputColumns（6 种类型）、选参考列、定范围、Prompt 双向编译。适合需要精细控制的场景。

**解决的问题**：用户想用 AI 为每行新增分析列（情感倾向、问题分类、翻译结果等），不想手动逐行标注。

**核心变化**：翻译和打标合并为同一套「输出列」机制。翻译不再是独立功能，而是预设模板之一。

**核心交互**：
1. 选择 AI 参考列（多选，告诉 AI 分析时看哪些列）
2. 用自然语言描述需求，或选择预设模板（含翻译模板）
3. AI 生成 outputColumns 方案
4. 用户可查看/编辑/新增/删除输出列
5. 并发逐行打标，实时显示进度
6. 结果存入 labelingResults，可共享到摘要页或导出

**6 种输出列类型**：enum（单选）、multi_enum（多选）、hierarchical_enum（二级分类）、boolean、text、number。

**翻译作为预设模板**：选择翻译模板后，输出列为「翻译列」（key='translation'），走打标流程。翻译列随打标结果一起存入 `labelingResults.outputColumns`，下游（摘要页）通过 labelingResults 通道消费，无需独立的翻译列元信息字段。

**关键设计**：
- Prompt 双向编译：AI 生成方案 ↔ 用户编辑 prompt
- JSON 容错解析：统一走 `parseRobustJSON`
- 打标结果写入全局 labelingResults，供摘要页使用

### 3. 数据摘要（SummaryView，`/summary`）

**解决的问题**：用户有一张大表，想快速了解整体特征、分布、异常。

**核心交互**：
1. 可选输入分析主题，点击「AI 推荐分析列」自动选择重点列
2. 手动选择要分析的列（多选，默认全选）
3. 系统预计算列画像，再调用流式 AI 生成报告
4. 右侧实时显示 Markdown 报告

**列画像引擎**：自动检测列类型（数值/文本/枚举/布尔/日期/标识符），计算 min/max/mean/median/标准差/等距分布、值分布、高频词、日期范围、填充率。

**AI 打标结果回接**：labelingResults 的每个 outputColumn（含翻译列）作为「虚拟列」纳入画像分析。

## 意图驱动上传流程

重构后的核心入口体验：

1. 首页上传 Excel
2. 自动弹出 ImportIntentModal，展示**表格快照**（行/列数 + 列类型徽章）
3. **AI 一键分析**（默认自动触发，可在设置「AI 自动行为」关闭）：AI 读表格快照，推断 2-3 个任务目标建议（如「分析差评原因，定位物流负面评论」），用户点采纳即自动填好核心列+任务，或自行修改
4. 用户选择：核心处理列（必填）+ 任务（清洗/加工/摘要 多选）+ 任务说明（可选）
5. 提交后核心列写入 dataShare，任务说明写入 `dataShare.intentNote`
6. 首页显示数据集意图卡 + 对应任务的快捷入口按钮
7. 点击跳转到对应功能页

**意图上下文贯穿**（ADR 0008）：任务说明以「参考段」形式注入清洗/加工/摘要的 AI 调用（`formatIntentContext`），不覆盖各模块自己的目标字段，让 AI 区分「数据集整体任务（宏观）」与「本步骤聚焦（微观）」。

这替代了旧的「启发式列检测 + 模块推荐」机制，让用户显式表达意图而非靠系统猜测。

## 跨模块串联流程

```
上传 Excel（首页）→ 意图弹窗（核心列+任务）
  → 数据清洗（Hub 双模式）
  → 智能加工（翻译+打标）
  → 数据摘要（全表报告）
  → 导出最终结果
```

## API 配置

- **平台选择**：硅基流动（SiliconCloud）或 aiping.cn
- **API Key**：从对应平台获取
- **模型选择**：每个平台提供多个模型可选
- **并发数**：批量调用最大并发（默认 20，上限 100），遇限流自动降级
- **配置管理**：支持导入/导出/重置全部配置（JSON）

## 移动端支持

桌面端和移动端采用完全分离的双模板架构（详见 docs/adr/0005）：
- **桌面端**：左侧 Sidebar + 右侧内容区
- **移动端**（≤768px）：底部 Tab Bar（首页/清洗/加工/摘要）+ 折叠面板 + 表格横向滚动
- 所有业务逻辑在两端共享，只有展示层分离
