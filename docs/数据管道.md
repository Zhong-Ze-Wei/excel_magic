# 数据管道

## 核心数据流

用户上传 Excel 后，数据在各模块间通过 `dataShare` store 流转，实现"一次上传，多步串联"。

```
┌──────────┐     setSharedData()      ┌─────────────┐
│ HomeView │ ──────────────────────→  │ dataShare   │
│ 上传 Excel│  headers, rows, name    │ store       │
└──────────┘  autoDetect=true        │             │
                                     │ headers[]   │
                                     │ rows[]      │
                                     │ coreColumn  │
                                     │ sourceName  │
                                     └──────┬──────┘
                                            │ useGlobalDataSync composable 自动同步
                    ┌───────────────────────┼───────────────────────┐
                    ▼                       ▼                       ▼
            ┌─────────────┐        ┌──────────────┐        ┌──────────────┐
            │ CleaningView │        │ TranslateView │        │ AnalysisView │
            │ 清洗         │        │ 翻译          │        │ 打标         │
            └──────┬──────┘        └──────┬───────┘        └──────┬───────┘
                   │                      │                       │
                   │ setSharedData()      │ setSharedData()       │ setLabelingResults()
                   │ (写回清洗后数据)      │ (写回翻译后数据)       │ (写入打标结果)
                   ▼                      ▼                       ▼
            ┌─────────────────────────────────────────────────────────────┐
            │                    dataShare store                         │
            │  headers[] ← 可能被模块追加列（如"翻译结果"列）              │
            │  rows[]    ← 可能被模块修改（如清洗删除行后重新写入）         │
            │  labelingResults ← AnalysisView 完成后写入                  │
            └──────────────────────────┬──────────────────────────────────┘
                                       │
                                       ▼
                               ┌──────────────┐
                               │ SummaryView   │
                               │ 摘要          │
                               │ 读取 headers  │
                               │ 读取 rows     │
                               │ 读取          │
                               │ labelingResults│
                               └──────────────┘
```

## dataShare store 状态

```js
{
  headers: string[],          // 表头数组
  rows: any[][],              // 二维数据数组（每行是数组，按列索引访问）
  sourceName: string,         // 文件名或数据来源标识
  coreColumn: number,         // 全局核心处理列索引（清洗/翻译的默认目标列）
  labelingResults: {          // AI 打标结果，AnalysisView 完成后写入
    outputColumns: Array,     // 打标方案的 outputColumns 定义
    analysisMap: {            // 每行的打标结果
      [rowIdx]: { values: { [key]: any } }
    }
  } | null
}
```

## 各模块的数据读写行为

### Composables 数据流抽象层

各子模块不再直接操作 dataShare，而是通过 4 个 composable 间接访问：

| Composable | 职责 | 使用方 |
|-----------|------|--------|
| `useGlobalDataSync` | onMounted + watch(rows.length) 自动同步全局数据到本地 | 所有 4 个子模块 |
| `useFileUpload` | readFile + setSharedData + 错误处理 | HomeView 及子模块的上传功能 |
| `useExport` | 封装 exportToXlsx 调用 | CleaningView、TranslateView、AnalysisView |
| `useShare` | setSharedData + 路由跳转 / 应用到全局 | CleaningView、AnalysisView |

### HomeView（上传入口）

- **写入**：上传文件后调用 `setSharedData(headers, rows, fileName, true)`，`autoDetect=true` 触发启发式核心列推荐
- **读取**：展示 `dataShare.sourceName`、`dataShare.rows.length`、`dataShare.headers`

### CleaningView（数据清洗）

- **读取**：通过 `useGlobalDataSync` composable 自动同步，替代直接 onMounted + importGlobalExcel
- **核心列**：用户选择清洗目标列，写回 `dataShare.setCoreColumn()`
- **写入**：用户确认清洗结果后，通过 `useShare.applyToGlobal()` 写回 dataShare
- **导出**：通过 `useExport.exportData()` 导出
- **特殊行为**：`runCleaningPipeline` 只在本地 `rows` 上操作，不直接修改 dataShare。用户确认后才写回

### TranslateView（批量翻译）

- **读取**：通过 `useGlobalDataSync` composable 自动同步
- **核心列**：使用 `dataShare.coreColumn` 作为翻译源列
- **写入**：翻译完成后在 `headers` 末尾追加"翻译结果"列，`rows` 每行追加翻译值，通过 `useExport` 导出
- **缓存**：`translationCache` 内存缓存，相同文本不重复调用 AI。关页面后缓存清空

### AnalysisView（AI 打标）

- **读取**：通过 `useGlobalDataSync` composable 自动同步
- **写入**：打标完成后调用 `dataShare.setLabelingResults(plan.outputColumns, analysisMap)`，通过 `useShare.shareTo()` 共享或 `useExport` 导出
- **不修改** headers/rows，打标结果独立存储在 `labelingResults` 中

### SummaryView（数据摘要）

- **读取**：通过 `useGlobalDataSync` composable 自动同步 headers/rows
- **读取 labelingResults**：如果存在，将每个 outputColumn 作为"虚拟列"纳入列画像分析
- **不写入** dataShare，AI 报告只在本地 `summaryText` 中

## 核心列（coreColumn）机制

`coreColumn` 是 dataShare 中的一个全局索引，指向"当前最需要处理的列"。

**推荐逻辑**（`heuristicDetectCoreColumn`）：取前 15 行样本，计算每列的平均文本长度，最长的列被推荐为核心列。直觉：文本最长的列通常是评论/描述/反馈等需要处理的内容列。

**使用方**：CleaningView 和 TranslateView 的列选择器默认选中 `coreColumn`。AnalysisView 的参考列默认包含 `coreColumn`。

**局限**：如果最长文本列是 URL 或 ID 列，推荐会失误。用户可手动切换。

## AI 调用模式

| 模式 | 函数 | 使用场景 | 特点 |
|------|------|----------|------|
| 非流式 | `callAI` | 翻译、打标、方案生成 | temperature=0.3, max_tokens=2048 |
| 流式 | `callStreamingAI` | 数据摘要报告 | temperature=0.7, max_tokens=4096, SSE |
| 批量并发 | `callAIBatch` | 翻译整列、打标整表 | 信号量控制并发，默认 20 路，上限 100，429 自动降级 |

所有 AI 调用都从前端直接发 HTTP 请求到第三方 API，API Key 从 settings store 读取。
